# Product brief

## Product

Java Messenger Learning Project

## Users

- Beginner Java developers learning how a browser client communicates with a server.
- Developers manually testing a shared WebSocket chat room.

## Purpose

Provide a small, real-time messenger that is both usable and easy to study. The browser sends JSON through WebSocket, the Java server validates and persists accepted messages, and every connected client receives the server-authoritative result.

## Personality

Calm, technical, trustworthy, and welcoming to beginners.

## Experience principles

1. Make connection state visible at all times.
2. Use familiar chat patterns so networking concepts remain the focus.
3. Explain important states with short, plain-language copy.
4. Treat the Java server as authoritative for messages and timestamps.
5. Make keyboard use, focus, contrast, and error recovery work by default.

## Accessibility target

WCAG 2.2 AA contrast, semantic controls and landmarks, visible keyboard focus, useful labels, reduced-motion support, and status announcements for connection changes.

## Avoid

- Generic SaaS dashboards made from many floating cards.
- Gradients, glass effects, and decorative blur.
- Playful social-media clutter that distracts from learning.
- Hidden connection or error states.
